唯一的判据是同一句话：进了仓库，会不会产生一条会变红的检查？不会的，不进。

授权怎么落的

母版授权是「保留所有权利 + 未获书面许可禁止再分发（含片段、改写、翻译）」。作者本人 2026-11-12 给出书面许可， 记录在 NOTICE.md：授权人、时间、原话、范围（分母与域、算子准入门、反模式、五级定义）、性质（解除第 1 条限制）。

顺手改掉一处过期声明。README 原写「不含任何私有文档片段」——全面吸取之后这句不再成立。 改成「结构来自作者本人专家包、措辞是本仓库自己的」，并把许可落到 NOTICE.md。 声明过期比没有声明更糟，它会让下一个人按错误的前提做事。

四条探针：管的是「坏味道」，形态与覆盖都看不见

上一版的漏洞很直接：结构看得见、覆盖看得见，但「这里有一处静默失败」看不见。 四条探针各答一个问题，每条都必须在一个真实目录上红过。

探针红在哪门槛 / 豁免真实命中（364 个被测对象的插件市场目录）
SWALLOW except 里只有 pass/continue/裸 return，异常被吞掉且不留痕 自著仓库 0 容忍；# noqa: swallow <理由≥4字> 豁免，计入黄不装成绿 RED excepts=25，裸吞 8 处
DUP 同一段话（≥80 字符、Jaccard ≥0.75）出现在 ≥3 份文档 2 份判黄；只管文档——代码重复归「零依赖单文件」这一取舍（C1.2） RED 21 组重复段落在 ≥3 份文件同时出现
ORPHAN 根级 *.md 或 cases/*/case.md 从 README.md 走不到 无豁免——走不到就是走不到 RED 该目录无 README，全部文档成孤儿
DEPS 有第三方 import 而仓库里没有 RUNTIME.md，或包名未登记 声明了但模块级导入只记信息，不判红（大多数项目本就如此） RED requests / yaml 未声明

三条自己踩出来的坑，都写进了代码注释

坑 1
中文 4-gram 把公共短语算成相似

第一版在自测里就误报：「判据」「变红条件」这类词在任意两段中文里都出现。 现在出现 >50 段的 shingle 直接不入索引——既是提速，也是精度。

坑 2
反模式表必然命中 A5

要描述「除某一类之外都适用」这个句式，就得把它写出来。不给隐藏跳过名单， 给一条写在案发现场的 <!-- a5-waiver: 理由 -->，并打印 waived=1。

坑 3
扫描面为 0 时不许报 PASS

空目录、无 .py、无 .md 一律输出 N/A 并打 SCAN files=0。 扫 0 个文件仍报绿，与「从不否决的闸门」是同一种东西。

L5 改判：删掉一条会惩罚诚实的判据

上一版 L5 是 absent ≥ 3 × covered。它当时的理由是「17 文件的仓库声称覆盖一半， 只可能是把提过当成做到」。这条理由本身没错，但它把手段当成了目的。

口径规则问题
旧 L5absent ≥ 3 × covered 覆盖上限被钉死在 25%。从 6 项做到 12 项，absent 90→83，判红。 于是「多做一个真判据」在账面上是扣分——越诚实越红
新 L5① 分母闭合（31 域 / 97 项算术对齐，--source 时与母版对撞）
② 每条 covered 在 runs/ 里有 FIRE 记录，且同一份证据含非 PASS 输出
③ text-only ≤ covered		 无。三条都机械可判，且「声明我有这个判据」的成本变成「它抓过真东西」
这是一个已经出现过的病灶，只是方向反了。 「从不否决的闸门」是永远绿；这条是永远红。两者都不是判据——判据必须有两条出路， 而且两条都有真实对象能走通。

换掉之后，账反而更硬

  • 分母可对撞：MAP.md 写 97 项 / 31 域；--source 指向母版时实测 97，一致才放行。 上一轮真踩过「覆盖率 4.31%→68.59% 全靠分母从 8569 掉到 538」的坑，所以分母必须能被打。
  • 声明要有现场：12 条 covered 各自对应一条 FIRE scripts/x.py::y，共 15 个判据点、8 份证据文件。
  • 账本自己对不上就红：域表与条目表双向校验（两边各写一遍，必然有一天对不上）； 合计行与实测不符也红。缺分母时标 UNVERIFIED，不判红——外部 clone 没有母版，不是他的错。

三处「判据自己的口径错了」

位置错在哪改法
L4 被测对象数probe 的 files= 只数代码文件：348 份文档 + 16 个脚本的目录被算成 16，证据直接判「样本不足」 统一成 subjects=（代码+文档），gate 三种格式依次认
L1 扫描面只扫 METHOD.md，于是 DOCTRINE.md 那批算子准入门从未被看过一遍 扫描面扩到两份；缺任一份即红
凭证模式只认 sk-/bearer/私钥，而本仓库每天用 GitHub token——40 字节真 token 摆着报 0 红 补 ghp_ / github_pat_，并加一条自测锁死
还有一个只在字节层才看得见的坑：Windows 子进程 stdout 是 CRLF，证据文件不归一到 LF， 上传后就是「内容对、字节不同」——上一轮 3 个 blob DIFF 正是这个病灶。这次在生成端 replace('\r\n','\n') 处理掉，34 文件无一含 CRLF。

类项判据 / 为什么要停

暂缓母版 13 个第三方技能 授权不在我手上，永久排除（已写进 NOTICE.md）
暂缓97 项逐条判据化 83 项在本仓库没有被测物。写成判据会永远绿——那是装饰，不是判据

这一版删了什么

  • 删了 L5 的比例判据（absent ≥ 3×covered）：它惩罚诚实，见④。
  • 删了 README 里重复的等级输出块：同一段输出抄两个文件，迟早对不上（DUP 探针立刻抓到）。
  • 删了 SHAPE.md 的「D>3 即红」：代码早已降级为只报数，文档没跟上——文档与代码不一致，比两个都错更难查。
  • 删了「不含任何私有文档片段」这句声明：全面吸取后它不再成立，改成授权记录。
一句话结论：这一版没有让仓库变大很多（25→34 文件），但让每一条声明都有了价格—— 说「我有这个判据」，就得拿出一份它红过的原始输出；说「覆盖了 12 项」，就得把 83 项缺席按域算平。 吸的是结构，长的是可判性。
