# 超级专家 · Super-Expert

> 这个称号不是自称。跑 `python scripts/gate.py --grade .`，它要么输出
> `GRADE super-expert (超级专家级)`，要么输出 `expert` / `not-yet` 并以非零退出。
> 五级逐条可复算，定义在 [`METHOD.md`](METHOD.md) 与 [`DOCTRINE.md`](DOCTRINE.md)。

一个极小的交付自检框架。**13 条判据，6 件仪器，3 个真实案例，0 依赖。**

它不教你做事。它只回答三个问题：

1. 我的改动**落地**了吗？
2. 落地之后**生效**了吗？
3. 我怎么知道**我的判据是假的**？

三问答不出，说明你手上只有"我觉得做完了"。

---

## 这个称号怎么判出来的

五级。前三级在仓库内就能独立验证；后两级需要**外部证据**，缺证据时输出 `UNKNOWN` 而不是 `FAIL`——
「判据没被执行过」和「判据不成立」是两件事。

| 级 | 判据 | 证据在哪 | 不满足时 |
|---|---|---|---|
| L1 判据完备 | 两份判据文件的每一条都带「变红条件」字段 | `METHOD.md` + `DOCTRINE.md` | 缺一条即红 |
| L2 判据可被证伪 | `falsify.py --selftest` 返回 0 | 现场跑 | 非零即红 |
| L3 真实案例 ≥ 3 | 四段齐全、粘了原始输出、判据能对上标题、`evidence/` 非空 | `cases/` | 任一条不满足即红 |
| L4 判据被真仓打脸 | 七条判据各自在 ≥20 文件的真实目录上非 `PASS` 过一次 | `runs/*.txt` 的 `ITEMS` 行 | 不足 3 份证据或某条从未红即红 |
| L5 覆盖诚实 | 分母闭合（97 项 / 31 域）＋ 每条 covered 有变红记录 ＋ `text-only ≤ covered` | `runs/cover-*.json` | 任一条不成立即红 |

```
$ python scripts/gate.py --grade .

等级判定
  L1 判据完备        PASS  13 条判据(METHOD+DOCTRINE)都带变红条件
  L2 判据可被证伪    PASS  selftest 4/4
  L3 真实案例 >= 3    PASS  3 个案例,四段齐全,判据可对上
  L4 判据被真仓打脸  PASS  5 个真仓证据, 7 条判据都红过
  L5 覆盖诚实        PASS  分母闭合 + 每条 covered 有变红记录 + text-only<=covered

GRADE  super-expert (超级专家级)
```

**L3 是这道门的第一道关键。** 自测能证明判据可运行，证明不了它抓到过真东西。
一个只在自造环境里跑绿的闸门，和从不否决的闸门是同一种东西——都会在最需要它的那天保持沉默。

**L4 追问「这些判据在真实目录上红过没有」**，防的是**只在夹具里成立**。
本仓库的凭据是 5 份 `runs/*.txt`：形态判定在三个真实目录上跑、通用探针在两个真实目录上跑，
七条判据各自至少红过一次（`SWALLOW=RED`、`DUP=RED`、`ORPHAN=RED`、`DEPS=RED`、`A5=RED`、`A2=RED`、`HUB=YELLOW`）。

**L5 追问「你敢不敢报未覆盖项」**，防的是**把提过当成做到**。上一版这里写的是
`absent ≥ 3 × covered`，已删除——原因见 [`MAP.md`](MAP.md) 第四节：那条判据会**惩罚诚实**，
覆盖从 6 项做到 12 项时它反而判红。现在的三条都可判：分母闭合、每条 covered 有变红记录、账面不许全是主张。

`cases/` 里三个案例都不是设计出来的场景，是同一天里真实拦下来的三次误判：

| 案例 | 发生了什么 |
|---|---|
| 001 | 状态码 `200` 但响应体 `0` 字节，被读成"通了"，据此给出一个根本不可能成立的方案 |
| 002 | CI 红了，但红在 `setup-python` 安装，被测物一行都没跑（`skipped` 不是 `failed`）|
| 003 | 上传"成功"、9 个文件字节全对、CI 全绿，但提交历史被压平（2 个只剩 1 个）|

三条有个共同点：**当时的检查全都通过了**。这就是为什么案例库比自测更值钱。

## 不做什么

划界比功能重要，这三条都是刻意的：

- **不是工作流引擎**。没有状态机、没有编排、没有 DAG。它只检查，不驱动。
- **不含任何领域知识**。具体法条、剂量、API 签名不在这里，也不该在这里。
- **不做自动修复**。它只负责变红，改是你的事——自动修复会让"红"失去意义。

## 不适用于

- 能力不到 20 个的系统。这个体量上，一张清单比一套判据更有效。
- 文件数不到 20 的仓库。比例类判据一律 `N/A`，此时它只能告诉你「样本不够」，说不出结构好坏。
- 需要实时决策的场景。命令是给人用的，不是给流水线用的。
- 你真的只想要一个"跑通就行"的原型。判据会拖慢你，那是它的本意。

## 30 秒上手

```bash
python scripts/gate.py --selftest      # 22 项：闸门自己会不会误判，含 L4/L5 的 8 条证伪
python scripts/pack_det.py --selftest  # 7 项：同样的树是否打出同样的字节
python scripts/falsify.py --selftest   # 4 项：能不能抓出一个假闸门
python scripts/shape.py --selftest     # 9 项：形态判据会不会假红（含 3 条「必须红」）
python scripts/cover.py --selftest     # 11 项：覆盖账会不会把「提过」算成「做到」
python scripts/probe.py --selftest     # 11 项：四条探针「该红会红」与「不该红不红」
```

六条都返回 `exit=0` 才算装好。任何一条非零，先修它，别往下用。

对你自己的仓库跑：

```bash
python scripts/gate.py /path/to/your/repo            # 三道扫描
python scripts/gate.py --grade /path/to/your/repo    # 五级判定
python scripts/shape.py /path/to/your/repo           # 形态判定（4 条，其中 1 条只报数）
python scripts/probe.py /path/to/your/repo           # 通用探针（吞异常/重复/可达/依赖）
python scripts/cover.py --source <你的能力清单> /path/to/your/repo   # 覆盖账
```

红项非零退出。黄项必须带 `文件:行`——没有出处的黄不算黄，算噪声。

**想拿 L4/L5，得自己攒证据**（这两级不认自述）：

```bash
# L4：在真实目录上跑，把输出存进 runs/
python scripts/shape.py D:/some/real/repo   > runs/shape-01.txt
python scripts/probe.py D:/other/repo       > runs/probe-01.txt
# L5：带母版分母算一次账
python scripts/cover.py --source cap.md --json runs/cover-01.json .
```

## 六件仪器各自解决什么

### `gate.py` — 三道检查 + 五级判定

| 检查 | 红 | 黄 |
|---|---|---|
| CRED 凭证 | 私钥、长 API key、GitHub token（`ghp_`/`github_pat_`） | 内网 IP |
| CRIT 判据 | 两份判据文件里任一条缺「变红条件」字段 | — |
| LIC 授权 | 无 LICENSE 文件 | 含「授权不明」标记的引用 |
| GRADE 等级 | L1–L5 任一级不达标 | — |

`--grade` 不是第四个扫描器，它是**把六件仪器串成一个称号的门槛**。
缺一级就降级：L1–L3 过 ⇒ `expert`；五级全过 ⇒ `super-expert`。

它自己也踩过两个坑，都写进了代码注释：

1. 判断「有没有变红条件」时**不能用子串匹配**——「没有变红条件」这句话本身就含那四个字。
   所以判据必须是标记行 `**变红条件**：`，不是关键词。
2. 凭证扫描原先只认 `sk-` / `bearer` / 私钥，**偏偏漏了本仓库每天在用的 GitHub token**：
   一个 40 字节的真 token 摆在那儿，扫描器报 0 红。现在 `ghp_` 与 `github_pat_` 各一条模式，
   并在自测里锁死（`github token => red`）。

CI 里跑的是 `--grade-l3`：只判仓库内可独立验证的三级。
L4/L5 依赖外部证据（真实目录样本、母版分母），缺它们是 `UNKNOWN` 不是红——
**让 CI 因为「没有私有文件」变红，会训练所有人忽略红。**

### `probe.py` — 四条通用探针

上一版只有形态与覆盖两件仪器，等于「结构」看得见、「坏味道」看不见。四条探针各管一件事：

| 探针 | 红在哪 | 门槛 |
|---|---|---|
| `SWALLOW` | `except` 里只有 `pass`/`continue`/裸 `return`，异常被吞掉且不留痕 | 自著仓库 0 容忍；可用 `# noqa: swallow <理由>` 豁免，计入黄 |
| `DUP` | 同一段话（≥80 字符、Jaccard ≥0.75）出现在 ≥3 份文档 | 2 份判黄；只管文档，代码重复归「零依赖单文件」这一取舍 |
| `ORPHAN` | 根级 `*.md` 或 `cases/*/case.md` 从 `README.md` 走不到 | 无豁免——走不到就是走不到 |
| `DEPS` | 有第三方 `import` 而仓库里没有 `RUNTIME.md`，或包名未登记 | 声明了但模块级导入只记信息，不判红 |

三条设计约束，都来自踩过的坑：

1. **扫描面为 0 输出 `N/A`，绝不报 `PASS`。** 扫 0 个文件仍报绿，与「从不否决的闸门」是同一种东西。
2. **高频 shingle 不参与相似度。** 中文短段用 4-gram 会把「判据」「变红条件」这类公共短语算成相似，
   造出假重复——第一版就误报过一次。现在出现 >50 段的 shingle 直接不入索引。
3. **豁免必须写在案发现场。** `# noqa: swallow 目录在遍历中途被删, 跳过是正确语义`——
   理由少于 4 字不算理由，豁免计入 `YELLOW`，不装成 `PASS`。

### `pack_det.py` — 确定性打包

普通 zip 会把 mtime、创建系统、权限位、文件顺序一起写进去。内容没变，字节变了，于是「下载包和源不一致」永远查不清。

固定四项：时间戳 `1980-01-01`、`create_system=3`、`external_attr=0644`、路径字典序。

判据是**重打一遍逐字节比**，不是公布一个固定哈希——后者只是让人抄数字，前者能自己复算。

它有两个已知陷阱，都已处理：产物文件若放在被包的树内部，第二遍会把自己打进去，导致永远"不一致"；ZIP 只存偶数秒，`utime` 设奇数秒会造成假差异。

### `falsify.py` — 检查器的检查器

这是六件里最该先有的。

```
python scripts/falsify.py \
  --checker "python scripts/gate.py {root}" \
  --good ./your/repo \
  --bad ./your/broken_fixture
```

两个方向都要过：

- 在 **bad** 上必须非零 —— 否则这个闸门**从不否决**
- 在 **good** 上必须零 —— 否则它**见谁都红**

**一个从不否决的闸门，在报告里和没有闸门完全一样。** 实测里见过一个 902 项"全绿"的检查表——
那个 902 在全库只出现过一次；四个闸门从不拦截。绿色不等于通过，可能只是没在看。

超时也算未通过，不得静默当成成功。

### `shape.py` — 形态判定

看的是**结构形状**，不是代码质量。判据写在 [`SHAPE.md`](SHAPE.md)，八条里只有三条做成了可执行检查：

| 检查 | 红在哪 | 门槛 |
|---|---|---|
| 尺度无关 | 文档里写了「某一类除外」的特例句，每处计 1 | 无 |
| 可归属 | `utils / common / misc` 这类目录占总文件数 > 10% | 文件数 < 20 不判 |
| 伪枢纽 | 目录下只有 1 个条目且仍是目录（包装层冒充分层） | 须查豁免表 |

另外一条（过度嵌套）**只报数不下结论**：实测四个真实目录，`r≥3` 的门槛恒不成立，放宽后又会恒红——恒 N/A 和恒红都不是判据。它输出的 `depth / r / deepest_avg` 给人看，判定交给「伪枢纽」和人工。

算子准入门（定序/派发/坍缩/组合）写在 [`DOCTRINE.md`](DOCTRINE.md)，其中「没有逆算子的坍缩是硬编码」一条没有可执行检查——它需要看接口能不能版本化，静态扫不出来，所以只作阅读材料，不占 L1–L5 的位置。

### `cover.py` — 覆盖账

回答一个问题：**你声称覆盖的那些能力，代码里真的有吗，红过吗。**

[`MAP.md`](MAP.md) 里 31 个域按算术闭合到 97 项，14 条有判据的逐条列出。`cover.py` 会真的打开文件核对，不信声明：

| 情形 | 结果 |
|---|---|
| 某域 covered + text-only + 缺席 ≠ 项数 | 红 |
| 域表与条目表对不上（两边各写一遍必然漂移） | 红 |
| 合计行与实测数不符，或 `--source` 分母与表里的 97 不符 | 红（分母漂移） |
| 声明 covered，但文件/标记不存在，或 `runs/` 里没有它的 `FIRE` 记录 | 红（没红过的判据不算判据） |
| `FIRE` 行在，但同一份证据里没有任何非 PASS 输出 | 黄，且该条不计入 covered |
| `text-only > covered` | L5 不成立 |

`FIRE` 行由真人真跑产生，格式固定：`FIRE scripts/probe.py::check_swallow`，同一份文件里跟着原始输出。
[`DOMAINS.md`](DOMAINS.md) 是另一本账：15 个跨域里只有 4 个有被测物。

## 它证明不了什么

诚实边界，写在这里比写在附录有用：

- **判据不能替你决定阈值**。"工具率低于 30% 算病"——30 是我这个场景的数，不是你的。
- **它不检查语义正确性**。代码能跑、账本完整、判据会红，都不代表业务算对了。
- **13 条不是完备集**。它们是我在自己的系统上反复翻车后剩下能站住的那些，不是穷举。
- **六件仪器只覆盖"自证"这一段**。你要证明"对用户有用"，那需要真实用户，任何脚本都替不了。
- **L5 的分母是别人的清单**。97 项怎么划的、31 域怎么分的，是母版的决定；这个仓库只能保证
  「这 97 项里我碰了 12 项，其余 83 项真的没有」，保证不了那份清单本身划得对。

## 为什么是这 13 条

每条都对应一次真实的判断失误，不是从方法论里抄的。举两个：

**目录不得冒充架构。** 一个名叫"智能体"的目录，四个文件共 569 行，全是工具函数与自测；真正的主循环在另一处，11,037 行。按目录巡检会得出"这一层健康"的结论，误差 19 倍。

**任何数字两个口径。** 同一个统计接口报 200,实际 4,420,差 22.1 倍。原因:把**分页大小**当成了总数。只用一个口径,这个错永远不会被发现。

剩下十一条见 `METHOD.md` 与 `DOCTRINE.md`，每条都带「变红条件」——这是闸门 CRIT 会强制要求的字段。

---

## 这批判据从哪来

`METHOD.md` / `DOCTRINE.md` / `MAP.md` / `DOMAINS.md` / `SHAPE.md` 是**判据层的改写**：
结构（分母、域划分、准入前提、变红条件）来自作者本人的专家包，措辞是本仓库自己的。
授权记录、改写范围与三处明确排除见 [`NOTICE.md`](NOTICE.md)。

上一版这里写的是「不含任何私有文档片段」。**那句话在全面吸取之后不再成立**，
所以改成了现在这句，并把许可记录落在 `NOTICE.md` 里——**声明过期比没有声明更糟**，
它会让下一个人按错误的前提做事。

`cover.py --source` 是**可选**的：指向一份能力清单能让它算出全量覆盖账；
没有那份文件，分母退回本表合计行并标注「未核验」——不判红，因为外部 clone 这个仓库的人没有那份清单。
