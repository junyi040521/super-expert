# 超级专家 · Super-Expert

> 这个称号不是自称。跑 `python scripts/gate.py --grade .`，它要么输出
> `GRADE super-expert (超级专家级)`，要么输出 `expert` / `not-yet` 并以非零退出。
> 判定条件见 [`METHOD.md` 附录](METHOD.md)，五级逐条可复算。

一个极小的交付自检框架。**七条判据，五件仪器，三个真实案例，零依赖。**

它不教你做事。它只回答三个问题：

1. 我的改动**落地**了吗？
2. 落地之后**生效**了吗？
3. 我怎么知道**我的判据是假的**？

三问答不出，说明你手上只有"我觉得做完了"。

---

## 这个称号怎么判出来的

五级。前三级在仓库内就能独立验证；后两级需要**外部证据**，所以缺证据时输出 `UNKNOWN`，而不是 `FAIL`——「判据没被执行过」和「判据不成立」是两件事。

| 级 | 判据 | 证据在哪 | 不满足时 |
|---|---|---|---|
| L1 判据完备 | 七条判据都带「变红条件」字段 | `METHOD.md` | 缺一条即红 |
| L2 判据可被证伪 | `falsify.py --selftest` 返回 0 | 现场跑 | 非零即红 |
| L3 真实案例 ≥ 3 | 四段齐全、粘了原始输出、判据能对上 METHOD 标题、`evidence/` 非空 | `cases/` | 任一条不满足即红 |
| L4 形态判据被真仓打脸 | `shape.py` 在 ≥3 个真实目录（≥20 文件）跑过，且每条判据至少红过一次 | `runs/shape-*.txt` | 不足 3 份或某条从未红即红 |
| L5 覆盖诚实 | `absent ≥ 3 × covered`（未覆盖项必须远多于覆盖项） | `runs/cover-*.json` | 比例过于乐观即红 |

```
$ python scripts/gate.py --grade .

等级判定
  L1 判据完备        PASS  7 条判据都带变红条件
  L2 判据可被证伪    PASS  selftest 4/4
  L3 真实案例 >= 3    PASS  3 个案例,四段齐全,判据可对上
  L4 形态被判据打脸  PASS  3 个真仓证据, 3 条判据都红过
  L5 覆盖诚实        PASS  absent >= 3 x covered

GRADE  super-expert (超级专家级)
```

**L3 是这道门的第一道关键。** 自测能证明判据可运行，证明不了它抓到过真东西。
一个只在自造环境里跑绿的闸门，和从不否决的闸门是同一种东西——
都会在最需要它的那天保持沉默。

**L4 与 L5 是这一版新增的两道。** 理由是同一个问题的两个方向：

- L4 追问「这些判据在真实仓库上红过没有」，防的是**只在夹具里成立**。
- L5 追问「你敢不敢报未覆盖项」，防的是**把提过当成做到**。
  一个 20 个文件的项目声称覆盖了一个大体系的一半，只可能是后者。

一道反向的判据值得单独说：L5 要求 **`absent ≥ 3 × covered`**。
**未覆盖项必须远多于覆盖项，才算诚实。** 这条比任何「我们支持 N 项能力」都难糊弄。

`cases/` 里三个案例都不是设计出来的场景，是同一天里真实拦下来的三次误判：

| 案例 | 发生了什么 |
|---|---|
| 001 | 状态码 `200` 但响应体 `0` 字节，被读成"通了"，据此给出一个根本不可能成立的方案 |
| 002 | CI 红了，但红在 `setup-python` 安装，被测物一行都没跑（`skipped` 不是 `failed`）|
| 003 | 上传"成功"、9 个文件字节全对、CI 全绿，但提交历史被压平（2 个只剩 1 个）|

三条有个共同点：**当时的检查全都通过了**。这就是为什么案例库比自测更值钱。

## 不做什么

划界比功能重要，这三条都是刻意的：

- **不是工作流引擎**。没有状态机、没有编排、没有 DAG。它只检查，不驱动。
- **不含任何领域知识**。具体法条、剂量、API 签名不在这里，也不该在这里。
- **不做自动修复**。它只负责变红，改是你的事——自动修复会让"红"失去意义。

## 不适用于

- 能力不到 20 个的系统。这个体量上，一张清单比一套判据更有效。
- 文件数不到 20 的仓库。比例类判据一律 `N/A`，此时它只能告诉你「样本不够」，说不出结构好坏。
- 需要实时决策的场景。三条命令是给人用的，不是给流水线用的。
- 你真的只想要一个"跑通就行"的原型。判据会拖慢你，那是它的本意。

## 30 秒上手

```bash
python scripts/gate.py --selftest      # 19 项：闸门自己会不会误判，含 L4/L5 的 6 条证伪
python scripts/pack_det.py --selftest  # 7 项：同样的树是否打出同样的字节
python scripts/falsify.py --selftest   # 4 项：能不能抓出一个假闸门
python scripts/shape.py --selftest     # 9 项：形态判据会不会假红（含 3 条「必须红」）
python scripts/cover.py --selftest     # 6 项：覆盖账会不会把「提过」算成「做到」
```

五条都返回 `exit=0` 才算装好。任何一条非零，先修它，别往下用。

对你自己的仓库跑：

```bash
python scripts/gate.py /path/to/your/repo            # 三道扫描
python scripts/gate.py --grade /path/to/your/repo    # 五级判定
python scripts/shape.py /path/to/your/repo           # 形态判定（4 条，其中 1 条只报数）
python scripts/cover.py --source <你的能力清单> /path/to/your/repo   # 覆盖账
```

红项非零退出。黄项必须带 `文件:行`——没有出处的黄不算黄，算噪声。

**想拿 L4/L5，得自己攒证据**（这两级不认自述）：

```bash
# L4：在 ≥3 个真实目录上跑，并把输出存进 runs/
python scripts/shape.py D:/some/real/repo   > runs/shape-01.txt
python scripts/shape.py D:/other/repo       > runs/shape-02.txt
python scripts/shape.py D:/third/repo       > runs/shape-03.txt
# L5：带母版分母算一次账
python scripts/cover.py --source cap.md --json runs/cover-01.json .
```

## 五件仪器各自解决什么

### `gate.py` — 三道检查 + 五级判定

| 检查 | 红 | 黄 |
|---|---|---|
| CRED 凭证 | 私钥、长 API key | 内网 IP |
| CRIT 判据 | 某条判据缺「变红条件」字段 | — |
| LIC 授权 | 无 LICENSE 文件 | 含「授权不明」标记的引用 |
| GRADE 等级 | L1–L5 任一级不达标 | — |

`--grade` 不是第四个扫描器，它是**把五件仪器串成一个称号的门槛**。
缺一级就降级：L1–L3 过 ⇒ `expert`；五级全过 ⇒ `super-expert`。

CI 里跑的是 `--grade-l3`：只判仓库内可独立验证的三级。
L4/L5 依赖外部证据（真实目录样本、母版分母），缺它们是 `UNKNOWN` 不是红——
**让 CI 因为「没有私有文件」变红，会训练所有人忽略红。**

它自己也踩过一个坑，写进了代码注释：判断「有没有变红条件」时**不能用子串匹配**——「没有变红条件」这句话本身就含那四个字，会把检查器整个绕过。所以判据必须是标记行 `**变红条件**：`，不是关键词。

### `pack_det.py` — 确定性打包

普通 zip 会把 mtime、创建系统、权限位、文件顺序一起写进去。内容没变，字节变了，于是「下载包和源不一致」永远查不清。

固定四项：时间戳 `1980-01-01`、`create_system=3`、`external_attr=0644`、路径字典序。

判据是**重打一遍逐字节比**，不是公布一个固定哈希——后者只是让人抄数字，前者能自己复算。

它有两个已知陷阱，都已处理：产物文件若放在被包的树内部，第二遍会把自己打进去，导致永远"不一致"；ZIP 只存偶数秒，`utime` 设奇数秒会造成假差异。

### `falsify.py` — 检查器的检查器

这是三件里最该先有的。

```
python scripts/falsify.py \
  --checker "python scripts/gate.py {root}" \
  --good ./your/repo \
  --bad ./your/broken_fixture
```

两个方向都要过：

- 在 **bad** 上必须非零 —— 否则这个闸门**从不否决**
- 在 **good** 上必须零 —— 否则它**见谁都红**

**一个从不否决的闸门，在报告里和没有闸门完全一样。** 我的实测里见过一个 902 项"全绿"的检查表——那个 902 在全库只出现过一次；四个闸门从不拦截。绿色不等于通过，可能只是没在看。

超时也算未通过，不得静默当成成功。

### `shape.py` — 形态判定

看的是**结构形状**，不是代码质量。判据写在 [`SHAPE.md`](SHAPE.md)，八条里只有三条做成了可执行检查：

| 检查 | 红在哪 | 门槛 |
|---|---|---|
| 尺度无关 | 文档里写了「某一类除外」的特例句，每处计 1 | 无 |
| 可归属 | `utils / common / misc` 这类目录占总文件数 > 10% | 文件数 < 20 不判 |
| 伪枢纽 | 目录下只有 1 个条目且仍是目录（包装层冒充分层） | 须查豁免表 |

另外一条（过度嵌套）**只报数不下结论**：实测四个真实目录，`r≥3` 的门槛恒不成立，放宽后又会恒红——恒 N/A 和恒红都不是判据。它输出的 `depth / r / deepest_avg` 给人看，判定交给「伪枢纽」和人工。

三条设计约束：

1. **样本不足输出 `N/A`，且 N/A 不计入通过。** 否则 20 个文件的仓库会得到「全绿」的假象。
2. **豁免写在 `SHAPE.md` 的表格里，不写在代码里。** 写死等于留一个无人审计的后门。
3. **跳过判据自述文件。** 判据里要写模式示例，不跳过就会自己命中自己。

### `cover.py` — 覆盖账

回答一个问题：**你声称覆盖的那些能力，代码里真的有吗。**

`MAP.md` 里每一行声明都要指向一个能打开的文件与标记（`scripts/gate.py::CHECKS`）。`cover.py` 会真的打开文件核对，不信声明：

| 情形 | 结果 |
|---|---|
| 声明 covered，但文件或标记不存在 | 红 |
| 合计行与实测条目数不符 | 红（账本自己对不上） |
| 声明 covered 的脚本没有 `--selftest` | 黄 |
| `absent < 3 × covered` | L5 不成立 |

**读不到母版清单时输出 `unknown`，不是 `absent`。** 读不到不等于未覆盖——把前者判成后者，会让诚实报告变成惩罚，下一次就没人愿意报告了。

## 它证明不了什么

诚实边界，写在这里比写在附录有用：

- **判据不能替你决定阈值**。"工具率低于 30% 算病"——30 是我这个场景的数，不是你的。
- **它不检查语义正确性**。代码能跑、账本完整、判据会红，都不代表业务算对了。
- **七条不是完备集**。它们是我在自己的系统上反复翻车后剩下能站住的那些，不是穷举。
- **三件仪器只覆盖"自证"这一段**。你要证明"对用户有用"，那需要真实用户，任何脚本都替不了。

```
│   ├── 002-ci-red-is-not-code/        CI 红在环境安装，不在被测物
│   └── 003-flattened-history/         内容全对，历史被压平
├── runs/                     L4/L5 的外部证据（形态跑记录 + 覆盖账）
└── scripts/

    ├── pack_det.py           确定性打包 + 7 项自测
    ├── falsify.py            反向证伪 + 4 项自测
    ├── shape.py              形态判定 + 9 项自测

```

全部 Python 3.8+，纯标准库。

这条声明本身是可证伪的，所以 CI 里 3.8 不是写在文档里，而是钉在 `ubuntu-22.04` 上真跑
（3.8 已 EOL，`ubuntu-latest` 的 setup-python 不再提供它的预编译包）；另加一道
`ast.parse(feature_version=(3, 8))` 静态守卫，避免哪天 3.8 的 runner 下架后声明悄悄失效。

## 为什么是这七条

每条都对应一次真实的判断失误，不是从方法论里抄的。举两个：

**目录不得冒充架构。** 一个名叫"智能体"的目录，四个文件共 569 行，全是工具函数与自测；真正的主循环在另一处，11,037 行。按目录巡检会得出"这一层健康"的结论，误差 19 倍。

**任何数字两个口径。** 同一个统计接口报 200,实际 4,420,差 22.1 倍。原因:把**分页大小**当成了总数。只用一个口径,这个错永远不会被发现。

剩下五条见 `METHOD.md`，每条都带「变红条件」——这是闸门 CRIT 检查会强制要求的字段。

---

## 这批判据从哪来

`SHAPE.md` / `MAP.md` / `DOMAINS.md` 是**判据层的自述重写**，不是任何私有文档的摘录：

- 本仓库不含第三方文本，也不含任何「保留所有权利」的文档片段。能进 MIT，是因为这里只有**思想与代码**，没有别人的表达。
- 判据的措辞是本仓库自己的。你可以不同意措辞，但每条都配了「红在哪」，可以照着复算。
- `cover.py --source` 是**可选**的：指向一份能力清单能让它算出全量覆盖账；没有那份文件，它输出 `unknown` 并照常独立运行。

这条边界是刻意的。如果换个做法——把某份私有清单整段搬进 MIT 仓库——那么「授权不明即不可分发」这条原则，就会在这个仓库里第一个被违反。
