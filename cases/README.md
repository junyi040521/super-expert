# 真实案例库

自测只能证明「判据能跑」。它证明不了「判据抓到过真东西」。

一个只在自造环境里跑绿的闸门，和从不否决的闸门是同一种东西——
都会在你最需要它的那天保持沉默。

所以这个目录只收一种材料：**判据被真实世界打脸的现场**。
每条都必须是真发生过的，带命令、带原始输出、带改法。

## 收录标准

一个案例要进来，必须四段齐全：

| 段 | 要求 |
|---|---|
| `## 现场` | 哪台机器、什么时间、什么命令。要能被人照着复现 |
| `## 红` | 原始输出。粘贴自 `evidence/`，不许改写、不许只留结论 |
| `## 判据` | 指向 `METHOD.md` 里某一条的**完整标题**。挂空判据的案例不算数 |
| `## 修法` | 改了什么，以及改完怎么确认它不再红 |

外加 `evidence/` 至少一个非空文件，存原始输出。

`python scripts/gate.py --grade` 会逐个检查这四段是否齐全、
`## 判据` 是否真能对上 METHOD 里的标题、`evidence/` 是否为空。
任何一条不满足，等级判定就不会给「超级专家级」。

## 索引

| 编号 | 案例 | 打脸的判据 |
|---|---|---|
| 001 | 状态码 200 但响应体 0 字节，被当成「通了」 | 二 · 任何数字要有两个独立口径 |
| 002 | CI 红了，但红在环境安装，不在被测物 | 五 · 判据要指向被测物，不是指向你想象的位置 |
| 003 | 上传「成功」、文件齐全、CI 全绿，但提交历史被压平 | 六 · 判据必须能当场变红 |
| 004 | 名叫「测试超时」的用例从未触发过超时，却一直是绿的 | 六 · 判据必须能当场变红 |

四条都不是设计出来的场景。它们是同一天里真实拦下来的四次误判。

004 有一点和前三例不同，值得写在这里：前三例是**别人**的判据错了，
004 是**这个仓库自己的判据**错了——它已经拿到最高等级，名下却有一条从没变红过的断言。
工具不给自己开后门，只有一条路：把它当成一条真实案例收进来，并且连"当时为什么没被发现"一起写下。
